# CRD, design system and mock alignment audit

Audited and fixed on 2026-10-10. The scope was the 40 component requirements documents in [`specs/components/`](specs/components/README.md), the [design system](design-system/README.md) (`tokens/tokens.css`, `assets/components.css`, and the page fragments in `src/`), and the [mocks](mocks/README.md) generated by `mocks/build.py`.

## Summary

The repository checkers passed before the audit, but the three artifact sets disagreed in substance:

- **CRDs ahead of the design system.** The CRDs recorded about 70 measured decisions that `components.css` did not implement. The CRD renderings drew the required look with "specimen only, not product CSS" overrides and showed the shipped look in "current (drift)" frames. Examples: badges and buttons that overflowed at 200 % text, missing `.link`, `.toast--info`, `.tooltip--below`, `.menu--sheet`, `.pagination--simple`, `.topbar__panel`, `.sidebar__toggle`, `.textarea--auto-grow` and `.skeleton-group` classes, and missing forced-colours rules for nine components.
- **Mocks behind both.** The generated mocks predated the design system's corrections. They drew icons with text glyphs (✦ × ! ⌕ ✓ → ★) and named counts with `aria-label`. They had a number input for the rating, a `datetime-local` for the preferred time, cards with "Read"/"Unread" badges for notifications, a badge for the filter summary and an annotation badge on edge states. They used "Working…" busy labels, disabled offline submits, and roles on the wrong dialog element.
- **The design system citing mocks that did not show the component.** Pages listed source mocks without the component; for example, the radio group cited care and review, which had no radios. Several design-system pages also contradicted the CRD decisions: help text placement, error-summary role, toast persistence, and footer, breadcrumb and page-header behaviour on phones.
- **CRDs making stale claims.** Some CRDs named classes that did not exist (`form-layout`, `card--highlight`, `filters-dialog`) or tokens on the wrong pair. Some listed source mocks that lacked the component or put a form in the review-request confirmation dialog. Some disagreed with each other, for example on the badge count wording, the braider link name and checkbox stacking on phones.

All of these are now resolved. CRDs, design-system pages and mocks state the same markup, classes, copy and states. Every CRD rendering uses product CSS only. No "specimen only" rule and no "current (drift)" frame remains.

## Method and precedence

Six reviewers each took one component group: actions and overlays; text inputs and forms; choice controls and feedback; navigation; containers and data display; status and empty states. For each component they compared the CRD (`.md` and `.html`) with `components.css`, the design-system fragment, the relevant foundation and pattern pages, and the mocks. Conflicts were settled with these rules:

1. A CRD decision (D-n) backed by a measurement or a stated reason wins. The design-system CSS and pages, and the mocks, change to match it.
2. A CRD claim about the design system or the mocks that is false is corrected in the CRD.
3. When the design system and a CRD disagree and neither records a decision, the better-reasoned side wins: the design system for visual facts taken from the mocks, the CRD for API, behaviour and accessibility. The other side is corrected.
4. A rule that existed only as a CRD specimen moves into `components.css`, the design-system page documents it, and the specimen is deleted.

The mocks were then regenerated from one rewritten `mocks/build.py`, which applies every reviewer's requests. Icons come from the design system's `ICONS` registry, read from `design-system/build.py`, so the registry has one source. Two final reviewers then checked every mock-dependent statement in the CRDs and design-system pages against the generated mocks.

## Systemic findings

| # | Finding | Resolution |
|---|---|---|
| S-1 | 71 "specimen only" CSS overrides across the CRD renderings drew behaviour that `components.css` lacked. | Ported to `components.css` (tokens only, mobile-first) and deleted from every CRD `.html`, both top-level `<style>` and iframe `srcdoc`. |

## Mock catalog changes

- Error pages keep only `default`. The manifest marks loading and error not applicable.
- The `confirm` dialog state is removed (cancel appointment, sign out). `invalid` is marked not applicable for the review request, cancel, sign out and cookie preferences.
- Account settings gains a `failed` state. Its `success` state keeps the form, with an inline "Saved just now" status.
- 170 mocks (was 181). The coverage table in `mocks/README.md` was regenerated.

## Open questions for product

These are unchanged by the audit. They are recorded in the CRDs as needing confirmation:

- Top bar D-3: the phone menu as an overlay panel. Sidebar D-4: the sidebar's own toggle. Page header D-4: primary action last on phones.
- Error page D-3: the forbidden copy. Select D-7: closed value truncation at 200 % text.
- Toast D-9: whether a posted review can be withdrawn (no Undo shown).
- No-results screens show "Clear filters" twice, in the chip row and the empty state. Both CRDs require their own control.
- `.btn[aria-expanded="true"]` also styles the top bar's open menu button with the active fill. Button D-13 specifies the selector unscoped.
