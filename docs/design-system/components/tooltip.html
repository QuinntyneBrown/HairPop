Tooltip

A tooltip names an icon-only control or adds a short hint, on hover and on keyboard focus. It never holds anything the person must read to finish a task.

WCAG 2.2 AAAPG TooltipStatus: stable

Overview

Use a tooltip to show the name of an icon-only button ("Close dialog", "Edit request") or a short supplementary hint. If the information is needed to complete a task (a price rule, a cancellation policy) put it on the page as text or a field hint; tooltips need hover or focus and are easy to miss on touch. Never put links, buttons or form fields in a tooltip; use a menu or dialog instead.

  • Text: two to five words, no full stop.
  • With shortcut: the label followed by a <kbd> shortcut, for desktop power features.
  • Below (.tooltip--below): when there is no room above the trigger (a dialog's close button near the top of the panel or viewport) the bubble opens below and its arrow points up.

Anatomy

  1. Bubble--color-bg-inverse, --radius-sm, --space-1 × --space-2 padding, caption type, --shadow-2.
  2. Arrow4px triangle in the bubble colour, pointing at the trigger.
  3. TriggerA focusable control; linked with aria-describedby.

Sizes

Tooltips have one size; the bubble grows with its text up to one line.

States

The tooltip is hidden by default and appears when the trigger is hovered or receives focus (:focus-within); it hides on pointer leave, blur or Esc.

The bubble is inverse in both themes: dark grey with light text on light pages, light grey with dark text on dark pages.

Responsive behaviour

  • Tooltips sit above the trigger, centred. Near a viewport edge the product flips them below (.tooltip--below, arrow pointing up) or shifts them along the edge with the CDK Overlay so they never clip; when shifted, the arrow follows the trigger through --tooltip-arrow-x.
  • In the product the bubble renders in the CDK overlay, outside any scrolling panel, and takes pointer events so it can be hovered (WCAG 1.4.13). The in-place .has-tooltip reveal on this page and in the mocks is a static stand-in; inside a dialog panel the mocks open it below so the panel does not clip it, pushed to the panel's end edge with the arrow on the close button's centre.
  • On touch devices (hover: none) tooltips are never the only label: icon-only buttons keep an aria-label, and important hints are shown inline.
  • Text never wraps; a hint that needs a second line belongs on the page.

Theming

The tooltip reads --color-bg-inverse and --color-fg-inverse, which swap in the dark theme, so it always contrasts with the page. It sits on --z-tooltip, above toasts and dialogs.

Accessibility

Role and pattern

APG Tooltip: the bubble has role="tooltip" and an id; the trigger references it with aria-describedby. For an icon-only button the tooltip repeats the aria-label, so the name never lives only in the tooltip.

Keyboard

KeyAction
TabFocusing the trigger shows the tooltip.
EscHides the tooltip without moving focus (WCAG 1.4.13, dismissible).

Focus

Focus stays on the trigger; the tooltip is never focusable. It stays visible while the pointer moves onto it (hoverable) and until blur or Esc (persistent).

Labelling

Text matches the trigger's accessible name or adds a hint. Shortcuts use <kbd>.

Contrast

Tooltip text
Bubble edge on page

Forced colours replace the inverse background, so the bubble gets a 1px CanvasText border.

Motion

Fades in over --duration-fast after a 300ms hover delay and hides immediately; reduced motion removes the fade. Focus shows it without delay.

Touch

No hover on touch, so tooltips are an enhancement only. The trigger keeps its own 24px minimum target.

Content

  • Sentence case, no full stop, two to five words: "Edit request", "Close dialog".
  • Start with the verb for actions; use the noun for indicators ("Unread updates").
  • Never repeat a visible label; a button with text needs no tooltip.
