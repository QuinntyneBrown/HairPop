Component · Actions

Button

Buttons let people act: send a request, find braiders, cancel an appointment. One primary button per view tells them which action matters most.

WCAG 2.2 AANative <button>Status: stable

Overview

Use a button when activating it changes something: it submits, sends, cancels, opens a dialog or starts a process. Use a link when it only takes the person somewhere; a link that looks like a button (<a class="btn">) is still a link. Use a menu when one trigger offers several actions.

  • Primary is the one action the view exists for: "Send request", "See braiders for this style", "Post review". Never two per view.
  • Secondary (the default look) is every other action: "Find braiders", "Request a change", "Keep request".
  • Ghost sits inside dense surfaces: the dialog close button, toolbar and row actions.
  • Link looks like a link but is a low-emphasis action beside other buttons: "Cancel request" on the appointment card.
  • Danger is for destructive confirmations and appears only inside a confirmation dialog: "Cancel request", "Sign out".

Anatomy

  1. Leading icon (optional)1.25em square, inherits the label colour, aria-hidden="true".
  2. LabelA verb phrase in sentence case; it is the accessible name.
  3. ContainerHeight from --control-height-*, --radius-md corners, 1px border, horizontal padding --space-3/4/6.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this view, then check there is still only one primary.

Emphasis from highest to lowest; danger is reserved for destructive confirmations.
HTML
<button class="btn btn--primary" type="button">Send request</button>
<button class="btn" type="button">Find braiders</button>
<button class="btn btn--ghost" type="button">Edit details</button>
<button class="btn btn--link" type="button">Cancel request</button>
<button class="btn btn--danger" type="button">Cancel appointment</button>

As a link

Navigation that should look like an action, such as "See braiders for this style", uses <a class="btn">. It keeps link semantics: it goes somewhere, opens with a middle click, and is announced as a link.

Sizes

Medium is the default. Small lives in rows, toolbars and pagination; large is for hero and auth screens where the button is the whole point.

Heights --control-height-sm/md/lg (32/40/48px); padding --space-3/4/6; label --font-size-sm/md/lg.
HTML
<button class="btn btn--primary btn--sm" type="button">Small · 32px</button>
<button class="btn btn--primary" type="button">Medium · 40px</button>
<button class="btn btn--primary btn--lg" type="button">Large · 48px</button>

Pressed (toggle)

aria-pressed="true" uses the selected look shared with chips and the current nav link.
HTML
<button class="btn" type="button" aria-pressed="true">Saved</button>

Expanded (menu trigger)

aria-expanded="true" on a menu trigger holds the variant's active fill while the menu is open, without the 1px press offset.
HTML
<button class="btn btn--ghost" type="button" aria-haspopup="menu" aria-expanded="false">More actions</button>
<button class="btn btn--ghost" type="button" aria-haspopup="menu" aria-expanded="true">More actions</button>
<button class="btn" type="button" aria-haspopup="menu" aria-expanded="true">Sort: Best match</button>

Both themes

  • Loading keeps the button's width and label (for its accessible name), paints the label transparent, shows a spinner, sets aria-busy="true" and ignores further clicks. Progress text ("Sending your request…") goes to the form's live region.
  • Disabled uses the native attribute; it is not focusable and is 50% opaque. Prefer leaving a button enabled and explaining the problem on activation; the offline booking form, for example, keeps "Send request" enabled and answers with the offline banner.
  • Pressed uses aria-pressed for a two-state toggle; the label stays the same or the change is announced.

Responsive behaviour

  • Below --layout-breakpoint-md (768px) the primary action in a page header or form becomes full width; secondary actions follow beneath it (.form-actions, .page-header__actions do this for you).
  • In dialog footers, buttons share the row and wrap with the primary first in reading order on phones (flex-wrap: wrap-reverse) and last (rightmost) from 640px.
  • Medium (40px) and large (48px) buttons meet the 24px minimum target; on phones the primary action of a screen is large or full width so it reaches 44px.
  • Labels never truncate. Write them to fit one line at 360px (shorten the verb phrase if one does not). When text is enlarged, a label wraps inside the button (overflow-wrap: anywhere, --line-height-snug, --space-1 block padding) and the button grows in height, so nothing overflows the page (WCAG 1.4.4, 1.4.10).

Theming

The button reads only semantic tokens, mapped into component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-bg-active, --btn-height, --btn-padding, --btn-font-size) that each variant and size overrides. A theme changes semantic tokens; a one-off re-skin overrides component tokens; neither edits the rules.

/* A promotional banner with an inverse primary button */
.promo .btn--primary { --btn-bg: var(--color-bg-surface); --btn-fg: var(--color-fg-accent); --btn-border: var(--color-bg-surface); }

In the dark theme the accent lightens to plum 300 and the label flips to plum 950, so the pair stays above 7:1; danger does the same with the red ramp (red 300 with red 950 text).

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form; see the APG Button pattern. A link styled as a button stays an <a href>; never a <div> with a click handler.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
EnterActivates a button or follows a button-styled link.
SpaceActivates a <button> on key up (not a link).

Focus

The shared ring (2px --color-focus-ring, 2px offset) appears on :focus-visible only. The offset gap shows the surface, so the ring stays at least 3:1 against both the plum button and the page. A loading button keeps focus.

Labelling

The visible label is the accessible name. Icon-only buttons set aria-label with a verb and object ("Close dialog", "Edit request") and show a tooltip on hover and focus. Do not change the label while loading; announce progress through a live region.

Motion

Background, border and shadow transition over --duration-fast (120ms); the active state moves down 1px. Reduced motion zeroes the duration in the tokens. The loading spinner keeps turning because it is the only sign that work is in progress.

Touch

Medium and large buttons exceed the 24px minimum; a screen's primary mobile action is at least 44px tall. Small buttons (32px) only appear where neighbours are at least 8px apart.

Content

  • Labels are verb phrases in sentence case: "Send request", "Request a change", "Post review". Never "OK", "Submit", "Yes" or "Click here".
  • Name the object when context does not: "Cancel request" in the dialog footer, not "Cancel".
  • Pair a destructive action with a safe one that says what staying means: "Keep request" beside "Cancel request".
  • Keep labels to three or four words. Use the braider's first name when it adds confidence: "Request with Nia".
  • Do not swap the label for "Working…" while loading; the spinner and live region carry progress.
