Form field

A form field keeps a control's label, help, error and counter together, in the same order and spacing, so every question on every HairPop form reads the same way.

WCAG 2.2 AALayout primitiveStatus: stable

Overview

Every text field, textarea and select sits in a .field. It is not a control; it is the layout and wiring around one: the label above, help and error below, joined to the control by for and aria-describedby. Groups of checkboxes or radios use a <fieldset> with a <legend> instead.

The wrapper is a <div>, never a <label>: putting help or errors inside the label makes them part of the control's accessible name.

Anatomy

  1. Label.field__label, label font, <label for>.
  2. Optional marker.optional, regular weight, muted.
  3. ControlInput, textarea or select.
  4. Help.field__help, body-sm, muted; stays visible while an error shows.
  5. Error.field__error, body-sm, danger text with a warning glyph that is hidden from screen readers.

Parts are stacked with --space-1 (4px) between them; fields in a form are --space-4 (16px) apart.

Sizes

The wrapper has no size; it takes the size of its control and the form column.

States

The field shows its control's state and adds the error. The label never changes colour, so state is carried by the control edge plus the error text (SC 1.4.1).

Theme previews repeat the markup, so they omit ids; production fields always link help and error with aria-describedby.

Responsive behaviour

  • Labels always sit above the control; never beside it, at any width. Side labels break at 200% zoom and in translation.
  • The field fills its column; long labels and errors wrap.
  • Two fields share a row only from 768px and only when they are short and related (see form layout).

Theming

The field reads only text tokens: --color-fg-default for the label, --color-fg-muted for help and the optional marker, --color-danger-fg for errors and --color-fg-subtle for the counter. Each passes 4.5:1 on canvas, surface and raised surfaces in both themes.

Accessibility

Role and pattern

No role of its own. <label for="id"> names the control (SC 1.3.1, 3.3.2); aria-describedby lists help, then error, then counter ids; aria-invalid="true" on the control while the error shows. Groups use <fieldset> + <legend>.

Keyboard

KeyAction
TabReaches the control only; labels, help and errors are not focusable.

Focus

The control shows focus. When a submit fails, focus goes to the error summary, whose links move focus to each field.

Labelling

Errors appear on blur or submit, not while typing; once shown, they re-validate on input and disappear as soon as the value is fixed. The error's warning glyph uses CSS alternative text "" so it is not announced.

Motion

Errors appear without animation so their position is stable for magnifier users.

Touch

The label is part of the tap target for its control.

Content

  • Label: a noun in sentence case ("Phone"), no colon.
  • Optional marker: "(optional)" after the label, only when most fields are required.
  • Help: why or how, one sentence ("Nia may text you about timing.").
  • Error: what to do, with an example ("Enter a 10-digit phone number like 416-555-0148.").
