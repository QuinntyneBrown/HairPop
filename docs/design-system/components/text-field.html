Text field

Text fields collect short, typed answers: an email, a name, a phone number, a search. They always sit inside a form field with a visible label.

WCAG 2.2 AANative <input>Status: stable

Overview

Use a text field for a single line of free text the person knows: name, email, phone, password, a search term. It is always wrapped in a form field that supplies the label, help and error.

  • For more than one sentence ("Your review", "Hair details") use a textarea.
  • When the answer must be one of a known set (an offered time, a distance, a rating) use a select or radio group, not free text.
  • Pick the right type and autocomplete: phones show the right keyboard and password managers fill the field (SC 1.3.5).

Anatomy

  1. LabelVisible, above the field, from the form field.
  2. Value or placeholderBody font; the placeholder is an example, never the label.
  3. ContainerExactly 40px tall (value at --line-height-snug), 1px --color-border-strong, --radius-md, 12px horizontal padding.
  4. Help or errorLinked by aria-describedby.

Password with show toggle

Use at least 12 characters.
The toggle is a real button labelled "Show" with aria-pressed and aria-controls; the word alone names it, with no eye icon, so the password keeps room for its value at 320px and at 200% text. Paste and password managers stay allowed (SC 3.3.8).

Sizes

Medium is the default for every form. Small fits dense filter rows; large is for a hero search.

Heights --control-height-sm/md/lg (32/40/48px); text --font-size-sm/md/lg at --line-height-snug, so each size measures exactly its control height and a search box lines up with the 40px button beside it.
HTML
<input class="input input--sm" type="text" value="Small · 32px" aria-label="Small field example">
<input class="input" type="text" value="Medium · 40px" aria-label="Medium field example">
<input class="input input--lg" type="search" value="Large · 48px" aria-label="Large field example">

States

Hover darkens the border, focus replaces it with the 2px accent ring, invalid doubles the edge in danger red and adds the error message, read-only uses a sunken, dashed container, disabled flattens and dims.

Both themes

Responsive behaviour

  • Fields fill their column. Forms are one column below 768px; from 768px short related fields may pair in a .form-row (price and distance).
  • Text is 16px at every width so iOS does not zoom on focus; small fields are never used for typing on phones.
  • The search box in a filter row grows to fill the row and wraps the action below it when the row is narrower than its minimum (--layout-card-min, 18rem) plus the action.

Theming

Component tokens: --field-bg (--color-bg-surface), --field-fg, --field-border (--color-border-strong), --field-border-hover (--color-fg-muted), --field-height (--control-height-md; --control-height-sm/-lg on the size modifiers). In dark the field is grey 900 on a grey 950 page with a grey 450 edge (above 3:1), so fields stay findable without shadows.

Accessibility

Role and pattern

Native <input> with a matching type, a <label for>, autocomplete for personal data (SC 1.3.5), and aria-invalid plus aria-describedby for help and errors.

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the field; the show-password toggle follows the field.
EnterSubmits the enclosing form.
EscIn search fields, clears the value (native).
↑ / ↓In number fields, steps the value; never the only way to set it.

Focus

The border becomes the accent and a 2px ring sits flush (outline-offset: 0), so the focused field shows 3px of accent against the surface. On submit with errors focus moves to the error summary, not the field.

Labelling

Every field has a visible label (SC 3.3.2); placeholders are examples only. The error names the problem and the fix and is announced through aria-describedby. A field without a visible label (the gallery search) uses one aria-label and sits next to an obvious action.

Motion

Border colour and ring transition over --duration-fast; nothing moves. Reduced motion makes the change instant.

Forced colours

Every field gets a CanvasText border and its focus ring and border become Highlight; the invalid edge colour is lost, so the error text carries the state.

Touch

Medium fields are 40px tall and full width; tapping the label also focuses the field. The password toggle is a 40px button.

Content

  • Labels are nouns in sentence case: "Email", "Phone", "New password". No colon.
  • Mark the minority: "(optional)" when most fields are required.
  • Placeholders show format only: "name@example.com". Never instructions that disappear on typing.
  • Errors say what to do: "Enter an email address like name@example.com.", not "Invalid input".
  • Help text is one sentence about why or how: "Use at least 12 characters."
