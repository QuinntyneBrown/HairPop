Top bar

The top bar is the same on every HairPop screen: the brand, the four primary destinations, unread updates and Maya's account. It is how people move between styles, braiders and their appointments.

Overview

Every product screen starts with the top bar inside .product-shell. It holds exactly what a customer needs from anywhere: the HairPop brand (back to the style gallery), the primary navigation, the Updates link with an unread count, and the account link with Maya's first name. Keep page-specific actions out of it; they belong in the page header.

  • Desktop and tablet (from 768px) show the brand, the four primary links (Styles, Braiders, Appointments, Help), then Updates and the account link on the right.
  • Phones (below 768px) collapse the four links and the account link behind a menu button so every destination is still one tap away; Updates and its count stay in the bar.
  • Signed out (sign in, sign up, password and verification pages) there is no Updates link and the account link reads "Sign in".
  • Use sidebar navigation instead only for a future tool with more than six destinations, such as a braider studio.

Anatomy

  1. BrandSparkle icon + "HairPop" in --text-h4, --color-fg-accent; links to the style gallery.
  2. Primary navigation<nav aria-label="Primary"> of nav links, 44px tall; the current page uses aria-current="page".
  3. UpdatesAccount link with a count badge; the count is part of the visible name.
  4. AccountThe customer's first name; links to account settings.
  5. Container56px (--layout-topbar-height), surface background, bottom hairline, sticky at --z-sticky, side padding --layout-margin.

Sizes

The top bar has one height (56px, --layout-topbar-height) at every breakpoint; only its contents change.

States

The bar itself has no states; its links and menu button do. Pointer and focus states are forced with data-state; real pages use :hover, :focus-visible, aria-current and aria-expanded.

Nav links have no separate pressed look: the active (pointer down) state keeps the hover background. Navigation links are never disabled; a destination the customer cannot use (for example Appointments while signed out) still links, and the destination explains why.

Responsive behaviour

  • Below 768px (--layout-breakpoint-md): .topbar__nav and the account link (.topbar__account) hide and .topbar__menu shows. The menu button controls the panel (.topbar__panel) with aria-expanded + aria-controls; the panel lists the four links and then the account link. Updates stays in the bar at --font-size-sm.
  • From 768px: the four links and the account link show inline and the menu button hides; an open panel closes. At default text size nothing wraps; at 768px all four links fit with the brand, Updates and Maya.
  • Enlarged text: the bar wraps between items (flex-wrap: wrap, no row gap) and grows taller instead of scrolling sideways; labels never wrap inside themselves. The panel scrolls when it is taller than the viewport below the bar.
  • The bar is at least 56px tall and sticky at every width. scroll-padding-top on html equals the bar height plus --space-4, so focused or anchored content is never hidden behind it (WCAG 2.4.11).
  • Side padding follows --layout-margin (16 → 32 → 48px), so the brand lines up with the page content below.
  • At 320px the brand, Updates with its count and the menu button still fit; the account link moves into the menu panel.

Theming

The bar reads --topbar-bg (aliasing --color-bg-surface) and --color-border-default; links read the nav-link tokens. The phone panel reads the same --topbar-bg (the component copies it onto the overlay pane, which sits outside the bar; without it the panel falls back to the surface). Override --topbar-bg for a campaign or partner theme, never the rules. In the dark theme the surface becomes grey 900 over the grey 950 canvas so the bar still reads as a layer, the brand and current link turn plum 300, and the current-link background becomes plum 950.

/* A studio sub-brand with a sunken bar */
.studio .topbar { --topbar-bg: var(--color-bg-surface-sunken); }

Accessibility

Role and pattern

<header class="topbar"> is the page's banner landmark; the links sit in <nav aria-label="Primary">. The phone menu follows the APG Disclosure pattern: a <button aria-expanded aria-controls="primary-panel"> that shows a second <nav class="topbar__panel"> with the same label and links. It is not an ARIA menu and not a modal: the page stays operable and the links stay plain links in Tab order.

Keyboard

KeyAction
Tab / Shift+TabAfter the skip link, from 768px: brand, primary links in order, Updates, account. Below 768px: brand, Updates, menu button, then (when open) the panel's links.
EnterFollows a link.
Enter, SpaceOn the menu button: opens or closes the nav panel and toggles aria-expanded.
Tab on the last panel linkCloses the panel and moves on to the first focusable element after the bar.
EscWith the panel open: closes it and returns focus to the menu button.

Focus

The shared 2px plum ring with 2px offset. Opening the phone menu leaves focus on the button; Tab from the open button enters the panel's first link and Shift+Tab from that link returns to the button, so the panel follows the button in keyboard order even though the overlay pane sits at the end of the document. Choosing a link navigates client-side, and the new page moves focus to its <h1> (see page header); only a full page load starts at the skip link.

Labelling

The nav is labelled "Primary" (use a different label for any second nav on the page). The current page uses aria-current="page", never colour alone. The Updates link's accessible name must contain its visible text: "Updates" + count + visually hidden ", 2 unread" reads "Updates 2, 2 unread". Do not put a second aria-label on the badge inside the link. The menu button is labelled "Menu" and states its expansion.

Motion

Link background and colour change over --duration-fast. The phone panel appears without a slide; under reduced motion every transition is instant because the tokens zero the durations.

Touch

Nav links, the brand and the account links are 44px tall (--target-comfortable); the menu button is 40px square with at least 12px to its neighbours.

Content

  • Primary links are one-word nouns, in this order everywhere: Styles, Braiders, Appointments, Help.
  • The account link shows the customer's first name ("Maya"); in the phone panel it reads "Maya · account"; when signed out it reads "Sign in" and Updates is not shown.
  • "Updates" shows the unread count only when it is above zero; above 99 it shows "99+" with the full number in the hidden text.
  • The brand is the word "HairPop" with the sparkle icon; never a tagline in the bar.
