Pagination

Pagination splits long results, such as 126 styles or Toronto braiders, into pages, and says where the customer is.

WCAG 2.2 AA<nav> landmarkStatus: stable

Overview

Use pagination under a list or grid of results when there is more than one screen of items and people need to come back to a place in them: the style gallery, matching braiders and long appointment histories. The summary ("Showing 1–3 of 126") tells them how much there is before they page.

  • Numbered with summary is the default for results lists.
  • Simple previous/next suits short sequences where page numbers mean little, such as reviews on Nia's profile.
  • Prefer "Show more" (a secondary button that appends) for feeds where position does not matter, such as notifications.

Anatomy

  1. SummaryRange and total in --text-body-sm, --color-fg-muted.
  2. Previous / NextText links; the unavailable end is aria-disabled="true" with no href.
  3. Current pagearia-current="page": accent-subtle fill, accent border and label.
  4. Page link32px square minimum (--control-height-sm), --radius-md.

With many pages, show the first, the last, and two either side of the current page from 768px, with a non-interactive "…" (.pagination__ellipsis, hidden from assistive technology) for each gap of two or more pages: 1 … 5 6 7 8 9 … 42. A gap of exactly one page shows that number instead. Below 768px show only the first, the current and the last page: 1 … 7 … 42.

Responsive behaviour

  • Below 640px: the summary takes its own centred line above the controls (numbered variant; the simple variant keeps it between the arrows).
  • From 640px: summary and controls share one centred row.
  • Below 768px: the narrow window, first, current and last page ("Previous 1 … 7 … 42 Next" fits one row at 360px; at 320px "Next" wraps to a second centred row). From 768px: the wide window, current ±2. A ±1 window measured 387px and wrapped at 360px, so phones show the current page only.
  • Items stay 32px tall with 4px gaps. Previous and Next keep their words; arrow-only controls carry hidden labels.

Theming

Items read --color-fg-muted; hover reads --color-bg-subtle + --color-fg-default; current reads --color-accent-subtle + --color-accent + --color-fg-accent (the same selected look as chips and the current nav link). In the dark theme the current page becomes plum 300 on plum 950.

Accessibility

Role and pattern

<nav aria-label="Results pages"> landmark with plain links (each page has its own URL, so ?page=2 can be bookmarked). The current page has aria-current="page". An unavailable end is <a role="link" aria-disabled="true"> without href, so it is announced but not focusable.

Keyboard

KeyAction
Tab / Shift+TabMoves through available links; disabled ends are skipped.
EnterLoads that page.

Focus

The shared ring. After a new page loads, move focus to the results heading (or the list) and announce the new range ("Showing 4–6 of 126") so keyboard users do not restart at the top bar.

Labelling

Label the nav for what it pages ("Results pages", "Braiders pages"); a page with two paginations uses two labels. Number links read as "2"; when the context is unclear, name them "Page 2" with an aria-label that still contains the visible number (2.5.3). Icon-only previous/next carry hidden text ("Next reviews").

Motion

None beyond instant colour changes. Do not smooth-scroll to the results when reduced motion is set.

Touch

Items are 32px with 4px gaps, above the 24px minimum. On phones the narrow window shows three numbers at most, so the row fits at 360px.

Content

  • Summary formula: "Showing {first}–{last} of {total}" with an en dash; add the noun when the context is unclear ("of 12 braiders").
  • "Previous" and "Next", not "Prev", "«" or "Older".
  • Numbers use tabular figures (font-variant-numeric: tabular-nums on items and summary); totals above 999 use a grouping comma ("1,284").
