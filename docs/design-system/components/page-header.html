Page header

The page header opens every screen: a short eyebrow, the page's one <h1>, a subtitle with the facts that matter, and optional page actions.

Overview

Every product page uses one page header as the first thing in <main> (after an optional breadcrumb). It holds the page's only <h1> in the light display face, which carries HairPop's voice: "Find a style that feels like you", "Your appointment with Nia".

  • The eyebrow names the area: "Discover" for browsing screens, the area name ("Appointments", "Account") for account screens.
  • The subtitle carries the facts the customer checks first: "Request HP-1048 · Sat 24 Oct at 10:00 am · awaiting Nia’s reply."
  • Actions are page-level only, with one primary at most; actions about one card stay in that card.

Anatomy

  1. Eyebrow.eyebrow: overline, uppercase, wide tracking, --color-fg-accent, 8px above the title.
  2. TitleThe page <h1>: --text-h1 (light, fluid 40–68px), tight tracking, balanced wrapping.
  3. Subtitle.subtitle: body text, --color-fg-muted, 4px below the title, capped at 65ch.
  4. Actions (optional).page-header__actions: at the end of the row, aligned to the bottom of the title block from 768px.

Examples on this page use an <h2> styled as the title because this documentation page already has its own <h1>; product pages always use <h1>.

Sizes

One size. The title scales fluidly with the viewport through --font-size-4xl (40–68px); nothing else changes.

States

The header is static. Its actions follow the button states. While the page loads, the header stays real (it does not become a skeleton) because its copy is known before the data arrives.

Responsive behaviour

  • Below 768px: actions move below the subtitle and take the full width; the primary action is full width and comes first, secondary actions follow.
  • From 768px: actions sit at the end of the row, aligned to the bottom of the title block.
  • The title is fluid (40px at 360px, 68px from about 1280px) and wraps with text-wrap: balance; keep it under about 40 characters so it fits in two lines on phones.
  • 24px (--space-6) separates the header from the page content at every width.

Theming

The header reads --text-h1, --color-fg-default, --color-fg-accent (eyebrow) and --color-fg-muted (subtitle). In the dark theme the eyebrow becomes plum 300 and the subtitle grey 350 on the grey 950 canvas. A brand theme changes the display family through --font-family-display, never the header rules.

Accessibility

Role and pattern

No ARIA. The title is the page's single <h1>, and the document <title> starts with the same words ("My appointments — HairPop"). The eyebrow is a paragraph before the heading, not part of it, so the heading reads cleanly in a headings list.

Keyboard

KeyAction
Tab / Shift+TabThe header itself is not focusable; Tab reaches its actions in DOM order, which matches the visual order at every width.
EnterActivates an action.

Focus

The skip link targets <main id="main">, which starts with this header. After a client-side route change, move focus to the <h1> (with tabindex="-1") so screen-reader users hear the new page.

Labelling

The title names the page specifically ("Your appointment with Nia", not "Details"). Uppercase eyebrows are styled with CSS (text-transform), so screen readers read "Discover", not letter by letter.

Motion

Touch

Actions follow the button rules; on phones the full-width primary is at least 40px tall, and 48px when it is the screen's main action.

Content

  • Titles are warm and specific, in sentence case, without a full stop: "Find a style that feels like you", "Care for your knotless braids".
  • Subtitles hold facts separated by middle dots and end with a full stop: "Sat 24 Oct at 10:00 am · awaiting Nia’s reply."
  • Eyebrows are one or two words: "Discover" for browsing, the area name for account screens, none for auth, legal and error pages.
  • Never call a pending request "confirmed" in the title or subtitle.
