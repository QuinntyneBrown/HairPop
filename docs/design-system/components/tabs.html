Tabs

Tabs switch between views of the same content without leaving the page, such as Maya's upcoming and past appointments.

Overview

Use tabs to split one page into peer views that a person compares or switches between often: "Upcoming" and "Past" appointments, or "About", "Services" and "Reviews" on Nia's profile. Each tab shows a panel in place; the URL may update but the page does not reload.

  • Use the top bar or sidebar to move between different pages.
  • Use filter chips to narrow one list by attribute (Braids, Twists, Locs), as the style gallery does.
  • Never use tabs for steps in a sequence; use a single form or a stepper.

Anatomy

  1. LabelOne or two words, --text-label.
  2. Count (optional)A neutral or info badge with the number of items.
  3. Selected indicator2px accent bar on the bottom edge, --radius-xs top corners.
  4. Tab listHairline --color-border-default underneath; scrolls horizontally when it overflows.

Sizes

Medium (44px) is the default. Small (32px, .tabs--sm) is only for a tab set inside a card or dialog.

Both themes

Responsive behaviour

  • Tabs keep one row at every width. When they overflow, the list scrolls horizontally (overflow-x: auto, hidden scrollbar); scroll the selected tab into view on load.
  • On phones keep to four tabs or fewer and labels to one word, so at 360px at most one tab is partly hidden.
  • Tab height stays 44px at every breakpoint so it remains a comfortable touch target.

Theming

Each tab reads two component tokens: --tab-fg (label) and --tab-indicator (bottom bar). States set them from --color-fg-muted, --color-fg-default, --color-border-strong, --color-fg-accent and --color-accent. In the dark theme the selected label and bar become plum 300.

/* A neutral tab set inside a dense card */
.card .tab[aria-selected="true"] { --tab-fg: var(--color-fg-default); --tab-indicator: var(--color-fg-default); }

Accessibility

Role and pattern

APG Tabs with automatic activation: arrow keys move focus and select the tab, because panels are already loaded. role="tablist" with aria-label; each <button role="tab"> has aria-selected, aria-controls and a roving tabindex; each panel has role="tabpanel" and aria-labelledby. Switch to manual activation (Enter/Space) when a panel loads from the network.

Keyboard

KeyAction
TabMoves focus into the tab list (to the selected tab), then to the panel.
← / →Moves to and selects the previous / next tab, wrapping at the ends; disabled tabs are skipped.
Home / EndSelects the first / last tab.

Focus

The shared ring is drawn inside the tab (negative offset) so the scrolling list does not clip it. Focus stays on the tab after selection; the panel is reachable with Tab (tabindex="0" when it has no focusable content).

Labelling

The visible label is the tab's name. A count is read as part of the name ("Reviews 86"); add hidden text when the number alone is unclear ("Upcoming 1, 1 awaiting reply").

Motion

The indicator colour changes over --duration-fast; panels swap instantly. Nothing moves under reduced motion.

Touch

Tabs are 44px tall with 4px between them; small tabs (32px) are used only inside cards and dialogs.

Content

  • Labels are one or two words, nouns or adjectives, in sentence case: "Upcoming", "Past", "Reviews".
  • Order tabs by how often they are used; the first tab is selected by default.
  • Counts are plain numbers; never put a status word in a tab.
