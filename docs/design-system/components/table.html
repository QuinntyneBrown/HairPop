Table

A table compares many records across the same columns: requests by date, status and estimate. On HairPop it is the dense alternative to row cards, for people who manage several appointments.

WCAG 2.2 AANative <table>Status: stable

Overview

Use a table when people compare or scan many records with the same fields: appointment history, payouts, review moderation. Use row cards (.appointment-row) when there are only a few records or each needs a sentence of context, as on My appointments today. Use a description list for the fields of one record. Never use a table for layout.

  • Default: 12 × 16px cells, sunken sticky header.
  • Dense (.table--dense): 8 × 12px cells for long histories.
  • Sortable: header buttons with aria-sort.
  • Selectable: a checkbox column and a bulk action bar.
  • With row actions: actions appear on hover or focus, always visible on touch.

Anatomy

  1. CaptionNames the table; label type; can be visually hidden when a heading sits above.
  2. Header row<th scope="col">, label type in --color-fg-muted on --color-bg-surface-sunken; sticky.
  3. Row header and cellsThe identifying cell is <th scope="row"> in label type on the row's own background; cells have --space-3 × --space-4 padding, body-sm type, one line each, and a hairline row divider.
  4. Numeric cell.num: right-aligned, tabular figures.

Responsive behaviour

  • The table scrolls horizontally inside .table-wrap; the page never scrolls sideways. Keep the identifying column first so it is visible before scrolling.
  • Below 768px, a table with four columns or fewer may switch to row cards (.card.appointment-row) when the screen says so; My appointments uses cards at every width today.
  • Row actions are always visible under (hover: none).
  • Cell values stay on one line (white-space: nowrap), so a column is as wide as its longest value and a wide table scrolls inside the wrapper instead of breaking "Sat 24 Oct · 10:00 am" over several lines. A full-width empty or error row wraps.
  • While the table overflows, the wrapper is a focusable region named by the caption (role="region", aria-labelledby, tabindex="0") so keyboard users can scroll it; when it fits, it carries none of these.
  • The column header row is sticky only inside the wrapper's own scroll area. The wrapper scrolls horizontally only, so on the page the header scrolls away with the table: paginate long histories rather than nesting a vertical scroll area.

Theming

The table reads --color-bg-surface (wrapper), --color-bg-surface-sunken (header), --color-border-default (rules), --color-bg-subtle (hover) and --color-accent-subtle (selected). Dark theme keeps the same roles: a grey 925 header on a grey 900 body.

Accessibility

Role and pattern

A native <table> with <caption>, <th scope="col"> and a row header (<th scope="row">) for the identifying cell; see the APG Table pattern. Sortable headers contain a <button> and the <th> carries aria-sort. It is not a grid widget: cells are not focusable, only the controls in them.

Keyboard

KeyAction
Tab / Shift+TabMoves through sort buttons, checkboxes and row actions in order; focus within a row reveals its actions.
Enter / SpaceSorts by the focused column; toggles a checkbox; activates a row action.
← / → with the wrapper focusedScrolls a wide table horizontally; the overflowing wrapper is a tab stop.

Focus

The shared ring on the overflowing wrapper, sort buttons and row controls. Sort buttons look like header text but keep a 24px (--target-min) target. A row with focus inside gets the hover tint so the row being acted on is visible. In forced colours a selected row gets a Highlight inset outline, because the system removes its tint.

Labelling

The caption names the table. Row actions name their record ("View HP-1048"), and row checkboxes name theirs ("Select HP-0992"). An empty header over actions has visually hidden text "Actions". Loading tables set aria-busy="true" on the wrapper; skeletons are aria-hidden.

Motion

Row actions fade in over --duration-fast; reduced motion makes it instant. Skeleton shimmer pauses under reduced motion.

Touch

Row actions are small buttons (32px) separated by at least 8px and always visible on touch; checkboxes sit in a 24px target.

Content

  • Column headers are nouns in sentence case ("Request", "Braider", "Estimate").
  • Dates read "Sat 24 Oct · 10:00 am"; money is right-aligned with tabular figures; ranges use an en dash ("$180–$240").
  • Status is a badge with text, never colour alone.
  • Empty and error rows follow the empty-state formula: what is missing, why, and one action.

Sources

Core-set component: no mock uses a table yet. The data it would hold appears as row cards in:

  • pages/my-appointments/default (two appointments as row cards)
  • pages/my-appointments/long (paged appointment history ("Showing 1–2 of 6 appointments"), where a dense table would help once it grows)

Drift fixed during extraction: none in the mocks; the kit's sort arrows were typed glyphs that screen readers announced (now hidden with empty alt text in content), and row actions had no record names. Fixed in the stylesheet: row headers were painted like column headers (sunken, muted, sticky), so hover and selection stopped at the first cell; the last row's row header kept its rule; unsorted sort buttons kept the browser's button style and sorted ones were 23px tall; values wrapped over several lines on phones.
