Description list

A description list shows the facts of one record as label and value pairs: an appointment's service, time, estimate and location. Facts scan faster as pairs than as sentences.

WCAG 2.2 AANative <dl>Status: stable

Overview

Use a description list for the fields of a single record that people read rather than edit: the appointment detail, the review step of a booking, the account summary. Use a table to compare several records, and a form when the values are editable.

  • Horizontal (.dl): labels in a narrow column beside values from 640px; stacked on phones.
  • Stacked (.dl--stacked): label above value at every width, for asides and narrow cards.

Anatomy

  1. Term<dt>: label type in --color-fg-muted; sized to its longest label (max-content).
  2. Value<dd>: body type in --color-fg-default; can hold a badge or a link.

Sizes

One size; type follows the body and label roles.

States

Description lists are static. Values have three content states: present, pending (not known yet, said in words, muted) and missing (an inline danger status, then a retry link that names what it retries). A fact the record does not have is omitted, term and value. Never leave a value blank or show a dash alone.

Responsive behaviour

  • Below --layout-breakpoint-sm (640px) .dl stacks: each term sits above its value with 8px after the value.
  • From 640px the term column is as wide as the longest label and the value takes the rest; rows are 8px apart with 24px between columns.
  • Long values wrap inside their column; keep terms to three words so the label column stays narrow.

Theming

Terms read --color-fg-muted, values --color-fg-default; spacing reads --space-1/2/3/6. No component tokens: override the semantic text colours if a surface needs it.

Accessibility

Role and pattern

Native <dl>, <dt>, <dd>: screen readers announce the list and pair count. Do not wrap pairs in extra <div>s that break the grid, and do not fake pairs with paragraphs and bold text.

Keyboard

KeyAction
TabReaches only links or buttons inside values; the list itself is not focusable.

Focus

Not focusable; links inside values use the shared ring.

Labelling

The card heading above names the record. Terms are the labels; do not repeat them in the value ("Estimate: $180–$240" under "Estimate").

Content

  • Terms are short nouns in sentence case, no colon: "Preferred time", "Estimate".
  • Values use the product formats: "Sat 24 Oct · 10:00 am", "$180–$240", "about 5 hours".
  • Say why a value is not known yet ("Shared after Nia accepts") instead of leaving it blank.
