Badge

A badge labels status in a word or two, such as Awaiting reply or Confirmed, so people can scan a list of requests without opening each one.

WCAG 2.2 AADot + text, never colour aloneStatus: stable

Overview

Use a badge for a short, read-only status attached to something: an appointment's state, the unread count on "Updates", a "New" marker. It is not a button and not a filter. Use a chip for anything people can select or remove, and an alert when the status needs a sentence of explanation.

  • Tone badges (neutral, info, success, warning, danger) describe state. Pick the tone by what the person should feel, then write the word.
  • Solid is for the rare badge that must stand out on a busy photo or card ("New").
  • Count is the unread number on "Updates" in the top bar.

Anatomy

  1. Dot8px, currentColor; a shape cue beside the colour. Hidden on count badges.
  2. LabelOverline style: 12px semibold, uppercase, 0.14em tracking. One to three words.
  3. Pill24px tall, --radius-full, 8px horizontal padding; hugs its content and never stretches.

Variants

Tone follows meaning, and the words carry the meaning on their own: "Awaiting reply" is understandable in grey.

Sizes

Badges have one size (24px). Scale emphasis with tone, not size.

States

A badge is static: it has no hover, focus, active, disabled or selected state of its own and is never focusable. When it sits inside a link or card, the container owns the interaction; the matrix shows each tone in the places it appears, including a hovered container.

  • Changing status (Awaiting reply → Confirmed) is announced by the toast or live region that reports the change, not by the badge.
  • Unread notifications use an info badge plus a bold title; read ones drop the badge. Warning is reserved for something that needs action.

Responsive behaviour

  • The badge never wraps (white-space: nowrap) and never stretches: inside a .stack it keeps its own width (align-self: flex-start).
  • At 360px, keep labels short enough to sit beside a title: "Awaiting reply" is the longest status in the product.
  • The count badge stays visible at every width, even when "Updates" is the only nav item left in the top bar.

Theming

Component tokens --badge-bg and --badge-fg map to the status tokens (--color-warning-bg/--color-warning-fg and so on); --badge-height sets the pill. Dark mode swaps every tone to a deep tint with a light label (amber-950 behind amber-300), keeping text above 4.5:1.

/* A "Top rated" badge that borrows the accent */
.badge--accent { --badge-bg: var(--color-accent-subtle); --badge-fg: var(--color-fg-accent); }

Accessibility

Role and pattern

A plain <span>; the text is the content. No role is needed. Status is never colour alone (WCAG 1.4.1): the word says it, and the dot adds a non-colour cue.

Keyboard

KeyAction
TabSkips the badge; it is not focusable. A badge inside a link is read as part of the link's name.

Focus

None on the badge. The containing link or card shows the shared ring.

Labelling

Text badges need nothing extra. A count badge adds visually hidden words so it makes sense: 2<span class="visually-hidden"> unread</span>. Do not put aria-label on the link around it: "Updates 2 unread" keeps the visible label inside the accessible name (WCAG 2.5.3), where "Notifications, 2 unread" would not.

Motion

None. A changing count does not bounce or pulse.

Touch

Not a target. The link containing a count badge is 44px tall (.account-link).

Content

  • One to three words, written in sentence case in the source ("Awaiting reply"); CSS uppercases it.
  • Describe the state, not the action: "Confirmed", not "Confirm".
  • Use the same word for the same state everywhere: Awaiting reply, Confirmed, Completed, Cancelled.
  • Counts above 99 show "99+" with the hidden text " unread".
