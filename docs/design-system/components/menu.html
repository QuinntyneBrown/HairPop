Menu

A menu offers a short list of actions from one trigger, such as an account menu behind Maya's name. Use it when actions are related and rarely needed.

WCAG 2.2 AAAPG Menu ButtonStatus: core set

Overview

Use a menu when one trigger offers three to seven related actions that do not deserve their own buttons: an account menu (Account settings, Notifications, Sign out) or an appointment's overflow actions (Request a change, Message Nia, Cancel request). It is part of the core set; no mock uses it yet, and the mocks' top bar shows "Maya" as a plain link.

  • Do not use a menu for navigation between pages that people visit often; use the top bar links.
  • Do not use a menu to pick a value in a form; use a select or radio group.
  • If there are only two actions, show two buttons.

Anatomy

  1. TriggerA button with aria-haspopup="menu" and aria-expanded; chevron icon.
  2. Section label (optional)Overline style; groups items.
  3. Item32px tall, 12px padding, optional 16px icon and shortcut.
  4. PanelRaised surface, --radius-md, --shadow-3, 4px inner padding, 12rem minimum width.

Sizes

Menus have one size: 32px items. Use a sheet or a page when items need more room.

Responsive behaviour

  • The panel opens below the trigger, aligned to its start edge, and flips above or to the end edge when it would leave the viewport (CDK Overlay flexible positioning).
  • Below 640px a menu with more than five items opens as a bottom sheet (the dialog sheet layout) so items become full-width 44px targets.
  • Item labels do not wrap; the panel grows to the longest label up to min(20rem, 100vw - 32px) and truncates beyond that.

Theming

The panel uses --color-bg-surface-raised, --color-border-default and --shadow-3; items use --color-bg-subtle on hover and focus. In dark the raised surface is grey 800, lighter than the page, so the panel reads as elevated without relying on the shadow. Danger items read --color-danger-fg on --color-danger-bg when highlighted.

Accessibility

Role and pattern

APG Menu Button: trigger <button aria-haspopup="menu" aria-expanded aria-controls>; list role="menu" labelled by the trigger; items role="menuitem", menuitemradio or menuitemcheckbox with aria-checked; wrappers role="none"; dividers role="separator". Implement with Angular CDK Menu.

Keyboard

KeyAction

↑On the trigger: opens the menu and focuses the last item.
↓ / ↑Moves between items, wrapping; disabled items are focusable but inert.

TabCloses the menu and moves on in page order.

Focus

Focus moves into the menu on open (roving focus; the item background shows focus instead of a ring) and returns to the trigger on close. Clicking outside closes it without moving focus.

Labelling

The menu is labelled by its trigger (aria-labelledby) or an aria-label that names the object: "Appointment HP-1048 actions". An icon-only trigger needs aria-label ("More actions for HP-1048"). Shortcut hints are visible text only.

Motion

The panel scales in from 96% and fades over --duration-fast with --ease-enter; closing is instant. Reduced motion makes the entrance instant.

Touch

Items are 32px tall and full width with no gaps between them; on touch-only devices and below 640px, long menus become a sheet with 44px items.

Content

  • Items are verb phrases in sentence case: "Request a change", "Message Nia", "Sign out".
  • Order by frequency; put destructive items last, after a divider.
  • An item that opens a dialog needs no trailing "…".
  • The trigger says what the menu is about: the person's first name for the account, "More actions" for overflow.
