Skeleton

Skeletons hold the shape of content while it loads, so the page settles into place instead of jumping when the style cards, braider profiles or appointments arrive.

WCAG 2.2 AAaria-hidden + aria-busyStatus: stable

Overview

Use skeletons on first load of any screen whose layout you know: the style gallery, matching braiders, a braider profile, my appointments. They draw the structure that is coming (media, title, two lines of text) in neutral blocks with a soft shimmer.

  • A skeleton mirrors the loaded layout: the same grid, the same card, the same 3:2 media. It is not a generic placeholder.
  • For a short in-place refresh of something already on screen, keep the old content and show an inline spinner.
  • If loading fails, the skeleton is replaced by an error empty state, never left shimmering.

Anatomy

  1. Media block.skeleton--hero: 3:2 aspect ratio, --radius-md, same as the photo it stands for.
  2. Title bar.skeleton--title: 1.5em tall, 40% wide.
  3. Text lines.skeleton--text: one line of body text; the last line is 60% wide.
  4. Busy containerThe real card with aria-busy="true" and one visually hidden status message.

Five primitive blocks, sized in em so they follow the type they replace.

Sizes

Skeletons have no sizes of their own: each block takes the size of the content it stands for (em-based text, 3:2 media, control heights).

States

Skeletons are not interactive: no hover, focus, active or disabled. Their life has three visible states, plus failure.

BlockLoading (shimmer)Reduced motion (still)Loaded
Text

Gentle at the root · 4–7 hours

CircleNO
Hero (3:2)

Both themes

  • Loading: the shimmer sweeps once per --duration-loop-shimmer (1.4s) between --color-bg-subtle and --color-bg-subtle-hover.
  • Reduced motion: the sweep pauses (--motion-loop-state: paused); the blocks stay as still shapes.
  • Loaded: content replaces the blocks in one update, the container drops aria-busy, and the status message clears or gives a count ("12 braiders").
  • Failed: the whole region is replaced by an error empty state; partial failures replace only the failed card with a warning alert (see the braider profile "partial" mock).

Responsive behaviour

  • Skeletons live inside the real layout classes (.feature-grid, .detail-grid, .stack), so they reflow exactly like the content: one column on phones, two from 768px, three from 1024px.
  • Fill the first viewport, not a fixed number: the story-card pattern renders three placeholders and hides those after the second below 1024px (.skeleton-group > .story-card:nth-of-type(n+3)), so phones show two, tablets one row of two and desktops one row of three.
  • The appointment-row placeholder's body grows from a 21rem basis, so its button drops below at the same width as the loaded row's action.
  • Media blocks keep the 3:2 aspect ratio at every width, so the loaded photo lands in exactly the same box (no layout shift).

Theming

The shimmer is a gradient of --color-bg-subtle and --color-bg-subtle-hover, both semantic, so the dark theme gets grey 800 and grey 700 blocks that read as recessed on a grey 900 card. Corners use --radius-sm for text and --radius-md for media and controls.

/* Skeletons on an accent art panel */
.story-card__art .skeleton { background-image: linear-gradient(90deg, var(--color-accent-subtle) 25%, var(--color-accent-subtle-hover) 37%, var(--color-accent-subtle) 63%); }

Accessibility

Role and pattern

Every skeleton block is aria-hidden="true": it has no meaning to announce. The container that will hold the content sets aria-busy="true" while loading, and one polite role="status" message names what is loading ("Loading styles"). See WAI-ARIA aria-busy.

Keyboard

KeyAction
TabNot focusable. Skeleton cards contain no links or buttons; real controls (search, filters) outside the loading region stay usable.

Focus

Focus is not moved when content arrives. If focus was inside the region (a "Try again" button that started the reload), return it to the region's heading.

Labelling

One status message per loading region, never one per block. Name the content: "Loading styles", "Loading Nia’s reviews", "Loading your appointments".

Contrast

Skeleton blocks are decorative placeholders and exempt from 1.4.11; the status message is announced, not seen. The content that replaces them meets the text pairs:

Muted text that replaces a line
Body text that replaces a title

Motion

The shimmer loops on --duration-loop-shimmer with animation-play-state: var(--motion-loop-state); under prefers-reduced-motion it pauses and the blocks stay still. The shimmer is low contrast and slow, far below flash thresholds.

Forced colours

Backgrounds are removed in forced colours, so every block draws a CanvasText hairline outline and the loading layout stays visible.

Touch

Not a target. Do not make skeleton cards tappable; links appear only when content loads.

Content

  • The status message is "Loading" plus the content's name, in sentence case: "Loading styles", "Loading Nia’s profile".
  • No visible "Loading…" text on top of skeletons; the shapes already say it.
  • If loading passes about ten seconds, add a visible line under the region: "Still loading. Check your connection." with a Try again link.
