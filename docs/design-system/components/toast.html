Overview

Confirm or explain the result of a recent action. This component appears in notifications/booking-update/success.

Use it for this job; choose a different component when the interaction or information hierarchy changes.

Anatomy

  1. Semantic elementPreserves the native role and browser interaction.
  2. Visible contentNames the action, value, or status in plain language.
  3. Component classReads shared roles from the token stylesheet.

Responsive

Below 640px, span the safe viewport width at the bottom. At wider widths, cap the stack at 24rem and align it right.

Theming

The same markup appears in light and dark themes. Use the semantic roles in the token table; override a component token only for a local variation.

Accessibility

Role and keyboard

Tab and Shift+Tab follow DOM order; Enter or Space activates native controls, while links use Enter. Static content remains in reading order.

Focus and labelling

Keep the shared visible focus ring. The visible text supplies the accessible name; icon-only actions need an explicit label. Associate help and errors with the relevant control.

Contrast, motion, and touch

Text uses a 4.5:1 minimum, meaningful controls and focus boundaries use 3:1, and all actions keep a 24px minimum target with comfortable spacing. Reduced motion removes decorative transitions. Check the actual foreground and background pair in both themes on the Color foundation.

Content

Use sentence case. For toast, keep the wording concrete and close to the value or action it describes. Show “Awaiting reply” until the braider accepts; label a price estimate as an estimate.
