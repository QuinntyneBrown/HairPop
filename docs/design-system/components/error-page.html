Error page

Error pages keep HairPop’s shell around a full-page empty state when a whole page cannot be shown: it does not exist, this account cannot open it, the service failed, or the device is offline.

Overview

An error page replaces the page content, not the page: the top bar, navigation and footer stay, so the person can still go anywhere. Inside the main region it is a full-size empty state whose title is the page's h1, with one sentence and one recovery action.

  • Not found (404): the address is wrong or old. Recover with "Explore styles".
  • Forbidden (403): the page exists but belongs to another account (someone else's appointment). Recover with "Sign in".
  • Server error (500): HairPop failed. Say what did not happen ("Your booking request has not been resent"), offer "Try again" and show a reference id for support.
  • Offline: the device has no connection. Say what still works ("Saved appointment details remain available") and offer "Try again".

When only part of a page fails, keep the page and use a region error state or a warning alert instead.

Anatomy

  1. Product shellTop bar, navigation and footer stay, so every route out remains.
  2. IconSearch (404), lock (403), alert (500), wifi-off (offline) in a tinted circle.
  3. Heading and sentenceThe page's h1 (styled as the empty title) and one sentence on what happened and what is safe.
  4. Recovery actionOne primary action; a 500 page adds a reference id under it.

Variants

Four variants, one per cause. Each keeps the same structure and changes the icon, tint and copy. In production the title is <h1 class="empty__title">; these frames use a paragraph so this page keeps one h1.

Sizes

Error pages always use the full empty-state size inside the page's main region; compact is for regions inside a page.

Error pages are static responses. They have no loading or nested error state of their own; the interactive states belong to the recovery action.

Responsive behaviour

  • The shell behaves as on every page: top-bar links collapse below 768px; the footer wraps.
  • The empty state centres in .product-main with the full padding; on phones its actions stack and the primary action may be full width.
  • The reference id wraps rather than overflowing; it is selectable text so it can be copied into a support email.

Theming

Error pages add no tokens: they inherit the shell and the empty-state tokens (--empty-icon-bg, --empty-icon-fg). 404 uses the accent tint so a wrong link does not feel like a failure; 403 and offline use warning; 500 uses danger. The reference id uses --text-code in --color-fg-subtle.

Accessibility

Role and pattern

A normal page: skip link, header, nav, main and footer landmarks, and an <h1 class="empty__title">. The <title> names the error: "Page not found — HairPop". Serve the matching HTTP status (404, 403, 500).

Keyboard

KeyAction
TabSkip link, top bar, then the recovery and secondary actions, then the footer. The icon and text are not focusable.
Enter / SpaceActivate the recovery action.

Focus

On a full page load focus starts at the top as usual. In the single-page app, when a route resolves to an error page, move focus to the h1 (tabindex="-1") so the change is announced. After "Try again" fails, keep focus on the button and announce the result.

Labelling

The icon is aria-hidden; the heading carries the meaning. The reference id is plain text labelled "Reference:".

Motion

None beyond the shell. The page does not animate in, and "Try again" shows the button's loading state.

Touch

The recovery action is at least 40px tall and full width on phones when it is the only action.

Content

  • Heading in plain words, no codes: "We couldn’t find that page", "You can’t open this page", "HairPop needs a moment", "You’re offline".
  • One sentence on what happened and what is safe: "Your booking request has not been resent."
  • One recovery action: "Explore styles", "Sign in", "Try again". Add "Contact support" only for 500.
  • Never blame the person ("You typed the wrong address"). Never show stack traces.
  • 500 pages show "Reference:" with an id and time support can find.
