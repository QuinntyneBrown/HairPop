Pattern

Dialogs and overlays

A dialog interrupts Maya, so HairPop uses one only when she must decide or give a small piece of information before going on. Everything else stays on the page.

Overview

The mocks use seven dialogs: filter braiders, review request, cancel appointment, request a change, report a review, sign out and cookie preferences. Each opens from a page that stays behind a backdrop (inert), has a title and one sentence that says what will happen, a short body, and a footer with a safe action and one emphasised action. All are built with the dialog component on the Angular CDK Dialog.

  • Default: focus starts on the first field in a form dialog, and on the safe action ("Keep request") in a destructive confirmation.
  • Busy: the pressed button sets aria-busy; the dialog stays open and Esc is ignored until the request settles.
  • Invalid: field errors appear inline; a summary is only needed for more than one field.
  • Failed: a danger alert at the top of the body; values kept; focus returns to the emphasised button.
  • Success: the dialog closes, focus returns to the trigger, and a toast confirms ("Change request sent to Nia").

Responsive

  • Below 640px the panel is a bottom sheet: full width, top corners --radius-xl, footer sticky at the bottom above the safe area, buttons full width with the emphasised action first.
  • From 640px the panel is centred, 32rem wide (24rem small, 48rem large), and the emphasised action is last on the right.
  • The panel never exceeds the viewport height minus 48px; the body scrolls, the header and footer stay.

Accessibility

  • APG Dialog (Modal): role="dialog", aria-modal="true", labelled by the title and described by the sentence under it; the page behind is inert.
  • Focus is trapped while open; Esc and the close button dismiss; focus returns to the element that opened it.
  • One dialog at a time. If a decision needs another decision, the second replaces the first, never stacks on it.
  • Menus and tooltips are not modal: Esc closes them, tooltips never take focus, and a menu returns focus to its button.

Content

  • Confirmation titles are the question with the object: "Cancel request HP-1048?", "Sign out of HairPop?"
  • The description says the consequence for Nia or Maya, not "Are you sure?".
  • Buttons are verbs that answer the title: "Keep request" / "Cancel request". Never "Yes" / "No" or "OK".
  • The safe action names what staying means; avoid "Cancel" as the safe label in a dialog about cancelling.
