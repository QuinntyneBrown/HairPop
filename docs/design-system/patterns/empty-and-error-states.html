Pattern

Empty and error states

An empty or broken screen is still a screen Maya can use. Each one says what happened, why, and gives one way forward.

WCAG 2.2 AA

Overview

Empty and error states use one shape, the empty state: an icon in a tinted circle, a title, one sentence, and one primary action (plus at most one secondary). Full-page errors use the same shape inside the normal shell; see error page. The mocks show 46 of these across appointments, braiders, styles, notifications and the 404, 403, 500 and offline pages.

When to use which

SituationVariantPrimary action
Nothing exists yet (no appointments, no notifications)First-run, accent iconThe action that creates the first item: "Explore styles"
Filters or search returned nothingNo results, search icon, filters stay visible"Clear filters"; secondary: widen one filter
A list or page failed to loadError, danger icon (.empty--error)"Try again"; secondary: a safe place
Part of a page failedNot an empty state: a warning alert in place of that part"Retry reviews"
Wrong address, no permission, server down, offlineError page in the shellOne recovery: "Explore styles", "Sign in", "Try again"

Responsive

  • Centred at every width; text is capped at 36ch so lines stay short on desktop.
  • Actions wrap and centre on phones; the primary comes first. Error pages add .empty--stack-actions, which stacks the actions at full width below 640px.
  • Use .empty--compact inside cards and dialogs, full padding when the state replaces a page’s main content.

Accessibility

  • The icon is decorative (aria-hidden); the title is a real heading at the next level under the page’s h1.
  • When an empty or error state replaces content after a user action (applying filters, retrying), announce it once through the empty state’s own visually hidden role="status" span, written after the state renders ("No braiders match these filters"); use role="alert" only when a retry the person started fails again.
  • "Try again" is a button when it retries in place, a link when it reloads the page.
  • Error pages keep the skip link, top bar and footer so keyboard users can leave.

Content

  • Empty formula: title = "No [things] yet" or what is missing; text = when they will appear or how to get one; action = the verb that makes one.
  • No-results formula: title names the filter problem; text suggests the one change most likely to help.
  • Error formula: title "We couldn’t [verb] [thing]"; text says what is safe and what to try; action "Try again".
  • Never blame Maya and never say "Oops". Never use the same "Nothing here yet" on every screen.
