Content and tone

Write clear copy that earns confidence without promising unconfirmed details.

WCAG 2.2 AA

Overview

Write clear copy that earns confidence without promising unconfirmed details. The reference journey is pages/appointment-detail/default.

When

Use concrete verbs, sentence case, local date and time, and an explicit price status: typical, starting, estimated, or confirmed.

Choose this composition when its information and action hierarchy matches the task; keep a simpler component when one action is sufficient.

Structure

Use concrete verbs, sentence case, local date and time, and an explicit price status: typical, starting, estimated, or confirmed.

Awaiting reply

<span class="badge badge--warning">Awaiting reply</span>

States

A request is Awaiting reply until accepted. Errors describe what happened, preserve work, and name the next action.

Check default, loading or busy, empty where applicable, validation, success, error, and offline against the relevant mock states.

Responsive

At 360px, stack related elements in reading order and keep actions reachable. At 768px, allow compact pairs; at 1024px, use the wider grid without stretching prose beyond the measure token.

Accessibility

Use native landmarks and controls. Keep focus visible, follow the visual reading order, announce async results, and associate errors with fields. Modal compositions return focus to their trigger. Check both themes, reflow, zoom, and reduced motion.

Content

A request is Awaiting reply until accepted. Errors describe what happened, preserve work, and name the next action. Name the action or state in words; never rely on colour alone. Use the cast, dates, and price language in the source mock as an example, not as live data.
