Pattern

Navigation and page structure

The shell is the same on every customer screen: top bar, page header, content, footer. Maya always knows where she is and how to get back.

Overview

Every HairPop page uses the same shell: a skip link, the sticky top bar with Styles, Braiders, Appointments and Help, the account links (Updates with an unread count, Maya), a page header (eyebrow, h1, subtitle), the content, and the footer with Terms and Privacy. The order and names never change between pages (3.2.3, 3.2.4).

Back behaviour

  • Browser Back always works: filters and tabs that change the URL push history; transient states (a busy button, a toast, an open dialog) do not.
  • Detail pages link back up through the breadcrumb, not a custom "Back" button that guesses the previous page.
  • After a success state (request sent), the next step is a forward link ("View request"), and Back returns to the form with its values intact.

Responsive

  • From 768px the four area links sit in the top bar. Below 768px they move into a menu opened by a menu button (.topbar__menu) with aria-expanded and aria-controls; the account links stay visible.
  • Breadcrumbs collapse to the parent link only below 768px ("‹ Knotless braids").
  • The page header stacks title over actions below 768px; the primary action becomes full width.
  • The footer wraps its two groups onto two lines on phones.

Accessibility

  • Landmarks: header, nav aria-label="Primary", main id="main", footer; the skip link is the first focusable element.
  • One h1 per page, in the page header; the eyebrow is a paragraph, not a heading.
  • The Updates link’s name includes the count ("Updates, 2 unread"); the visual count badge is aria-hidden so it is not read twice.
  • scroll-padding-top matches the sticky top bar so focused elements are never hidden under it (2.4.11).
  • Nav links are 44px tall targets.

Content

  • Area names are single nouns: Styles, Braiders, Appointments, Help.
  • Eyebrows group pages: "Discover" for browsing screens, "Your HairPop" for Maya’s own data.
  • Page titles speak to Maya: "Find a style that feels like you", "Your appointment with Nia". The <title> puts the specific part first: "Request HP-1048 · HairPop".
  • Subtitles carry the key facts in one line, separated by " · ".
