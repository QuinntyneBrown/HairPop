Foundation

Layout

Mobile first: one column at 360px, more columns as space allows, and content that never runs wider than 1280px or prose wider than 65 characters.

Overview

Base styles target a 360px phone. Breakpoints only add: more columns, wider gutters and margins, the top-bar links, two- and three-column grids. Media queries are min-width in rem (48rem, 64rem) so they follow the reader's font size; the mocks also had two max-width queries (47.99rem, 39.99rem) that the system rewrote mobile-first.

  • Margin: viewport edge to content (--layout-margin).
  • Gutter: space between columns (--layout-gutter; card grids use --space-4).
  • Container: caps content at --layout-container-max and centres it.
  • Measure: caps prose at --layout-measure.

Custom properties cannot be read inside @media, so the rem values are repeated in queries by convention: @media (min-width: 48rem) means md. tokens.css updates --layout-columns, --layout-gutter and --layout-margin at md and lg; components read those instead of writing their own queries.

Usage

  • Start every layout at 360px and add columns with min-width queries; never write a max-width query to undo a desktop style.
  • Pages put content in .container; nothing touches the viewport edge except the top bar, banners and the footer rule.
  • Vertical rhythm: --space-6 between page blocks, --space-8 to --space-12 between page sections, --space-4 to --space-6 inside cards.
  • No two-dimensional scrolling at 320px except inside .table-wrap.
  • Media fills its column and keeps a 3:2 ratio (aspect-ratio: 3 / 2), so loading skeletons and art panels reserve the same space as the photo. The mocks sized art panels with spacing tokens (min-height: var(--space-12), hero calc(var(--space-12) * 4)), which made them shorter than photos.
