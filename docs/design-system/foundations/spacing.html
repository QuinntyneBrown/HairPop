Foundation

Spacing

Every gap, padding and margin is a multiple of 4px. Components stay tight inside (24px or less), layouts breathe between (24px or more), and three control heights keep buttons, inputs and chips aligned.

  • Overview
  • Scale
  • Inside and between
  • Padding by component size
  • Usage
  • Tokens

Overview

Spacing tokens are named by multiples of 4px: --space-4 is 16px, --space-0-5 is 2px. All values are in rem so they grow with the reader's font size. The mocks used the scale everywhere; only a handful of hairline offsets (1px negative margins for joined borders, 0.1rem icon nudges) sat off it, and the nudges now use --space-0-5.

Padding by component size

Controls come in three heights. Height and horizontal padding move together; the font steps with them.

Other fixed paddings: cards and dialogs --space-6; toasts and alerts --space-4; table cells --space-3 × --space-4; menus --space-1 around with --space-3 inside items; fact tiles --space-3.

Usage

  • Use a token for every margin, padding and gap. If no step fits, the design is wrong, not the scale.
  • Prefer gap on .stack, .cluster and grids over margins on children.
  • Components use --space-6 or less inside; layout uses --space-6 or more between.
  • Spacing never scales with viewport width. At a breakpoint the layout tokens (--layout-gutter, --layout-margin) change instead.
  • Do not borrow spacing tokens for element sizes. The mocks sized the profile avatar and the art panel with --space-12; those now use avatar size tokens and a 3:2 aspect ratio.
