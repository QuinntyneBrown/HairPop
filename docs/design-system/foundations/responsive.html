Foundation

Responsive

HairPop is used on a phone in one hand while choosing a style. Every screen starts at 360px and gains columns, navigation and space as the viewport grows.

  • Overview
  • Breakpoints
  • Behaviour by component
  • Type and space
  • Usage

Overview

Base styles target a 360px phone. Breakpoints only add: more columns, the top navigation links, centred dialogs, docked toasts. Nothing is designed desktop-first and squeezed down.

  • Use min-width media queries only, written in rem (48rem, 64rem) so they move with the person's font size. The mocks' max-width: 47.99rem overrides were rewritten mobile-first.
  • Prefer tokens that already change with the viewport (--layout-columns, --layout-gutter, --layout-margin) over new queries.
  • Custom properties cannot be used inside @media, so the breakpoint values are repeated there by convention; the canonical values are the --layout-breakpoint-* tokens on the layout page.

Type and space

  • Body and UI text use fixed steps from the type scale so they follow browser zoom. Only the display and h1 sizes are fluid, through clamp() inside --font-size-4xl and --font-size-5xl.
  • Spacing never scales with viewport width; a breakpoint swaps the token (for example --layout-margin from 16 to 32 to 48px).
  • Prose stays under --layout-measure (65 characters) at every width.

Usage

Touch and pointer

  • Targets are at least 24×24px everywhere and 44px for a screen's primary mobile action, nav links and tabs. (pointer: coarse) is not used to grow targets; they are already large enough.
  • Under (hover: none), hover-only affordances (table row actions) are always visible.
  • Nothing depends on hover alone: tooltips also open on focus, and every hover reveal has a tap or keyboard path.

Viewport edges

  • Fixed bottom elements (bottom sheets, the toast region) add env(safe-area-inset-bottom) so the home indicator never covers an action.
  • Full-height layouts use 100dvh, so mobile browser toolbars do not clip the footer.
  • No page scrolls horizontally at 320px; only tables, code and tab lists scroll inside their own wrappers.

Accessibility

  • Reflow (WCAG 1.4.10): every screen works at 320 CSS px, which is 1280px at 400% zoom, without two-dimensional scrolling.
  • Orientation (1.3.4): nothing locks to portrait or landscape.
  • Resize text (1.4.4): sizes are in rem, so 200% text size enlarges everything and breakpoints follow.
  • Focus not obscured (2.4.11): the sticky top bar is matched by scroll-padding-top, so a focused field never hides beneath it.
