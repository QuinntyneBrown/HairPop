Foundation

Theming

Themes change what a role looks like, never which role a component asks for. Light and dark ship today; the same mechanism carries a partner or high-contrast theme.

Overview

All colour and elevation in HairPop is read through semantic tokens such as --color-bg-surface or --color-fg-accent. A theme is a block in tokens/tokens.css that gives those tokens different values. Components, pages and the mocks never know which theme is active.

How themes are applied

  1. Light is the default. Its themed tokens live in :root, [data-theme="light"], so a light preview nested inside a dark page (like the left panel above) re-declares them. Layout, type and spacing tokens stay on bare :root and keep inheriting.
  2. Dark applies with [data-theme="dark"] on any element, usually <html>.
  3. Operating-system preference: the same dark values sit inside @media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { … } }, so a person who prefers dark gets it unless the product forces light. The two dark blocks must stay identical; copy one into the other when you change either. check_contrast.py reads both.
  4. color-scheme is set in each theme so native controls, scrollbars and autofill follow.
<html lang="en">                    <!-- follows the OS -->
<html lang="en" data-theme="dark">  <!-- forced dark (saved preference) -->
<html lang="en" data-theme="light"> <!-- forced light -->

Persist a person's explicit choice and set the attribute before first paint to avoid a flash. The documentation pages honour ?theme=dark, and the t key toggles.

Dark is designed, not inverted

  • Surfaces get lighter as they rise: canvas (grey 950) < surface (grey 900) < raised (grey 800). Dialogs read as raised because they are lighter, not only because of a shadow.
  • The plum accent lightens to plum 300 and text on it flips to plum 950; danger does the same with red.
  • Status backgrounds become deep tints (green 950, amber 950, red 950) with light text.
  • Shadows are darker and more opaque, because a soft grey shadow disappears on a dark canvas.

/* primitive */ --palette-plum-600: …;
/* semantic  */ --color-accent: var(--palette-plum-600);         /* dark: var(--palette-plum-300) */
/* component */ .btn--primary { --btn-bg: var(--color-accent); }

Adding a theme

  1. Add any new primitives the theme needs to the primitive section of tokens.css.
  2. Add a [data-theme="<name>"] block that overrides semantic tokens only. Start by copying the light block's colour section; set color-scheme.
  3. Run check_contrast.py tokens/tokens.css; every pair in contrast-pairs.json must pass for the new theme too.
  4. Run tokens_to_json.py to refresh tokens.json, and add the theme to the screenshot matrix.
/* A partner salon theme: teal accent, everything else inherited */
[data-theme="partner"] {
  --color-accent: var(--palette-teal-700);
  --color-accent-hover: var(--palette-teal-800);
  --color-fg-accent: var(--palette-teal-800);
  --color-focus-ring: var(--palette-teal-700);
  color-scheme: light;
}

Contrast and forced colours

  • prefers-contrast: more raises decorative borders to --color-border-strong and muted and subtle text one step towards --color-fg-default.
  • forced-colors: active (Windows High Contrast) hands the focus ring to Highlight and borders to CanvasText; components add a system-colour border so cards, chips and inputs keep their edges, and selected nav links, tabs and chips get a Highlight outline.
  • prefers-reduced-motion is handled by the motion tokens; see Motion.

Consuming tokens.json

tokens/tokens.json is generated from tokens.css by tokens_to_json.py in the W3C Design Tokens (DTCG) format, for native apps, email templates and anything that cannot read CSS.

  • Each token has $type and $value; aliases are written {palette.plum-600} so the tier relationship survives.
  • Dark values sit under $extensions on the same token, so a platform build resolves both themes from one file.
  • Never edit tokens.json by hand; change tokens.css and regenerate.

Usage

Accessibility

Every theme meets WCAG 2.2 AA for every pairing in tokens/contrast-pairs.json: 4.5:1 for text and 3:1 for control edges, focus rings and meaningful icons. The colour page shows each pair with its live ratio; switch the theme to see the other values. A theme that fails any pair is not shipped.
